Okapi BM25 keyword retrieval, implemented in Python.

## How it works

It stores documents in a Python list per group of [tasks](../reference/task.md), using the same
lowercase, letter-and-digit tokenizer as [`TFIDF`](tfidf.md).

BM25 weights query terms by rarity and limits the contribution of repeated occurrences.
`k1` controls term-frequency saturation; `b` controls normalization for document length relative
to the corpus average. The inverse document frequency is
`ln(1 + (N - df + 0.5) / (df + 0.5))`, where `N` is the document count and `df` the number
containing the term. Smoothing keeps this weight positive even for common terms.

The defaults are `k1=1.5` and `b=0.75`. Set them with `BM25(k1=1.2, b=0.6)` and record any
changes with your comparison. Documents scoring zero are excluded; the rest are returned in
descending score order.

## Why it matters

BM25 is a standard keyword retrieval baseline. Compare your system with it under the same
tasks, retrieval limit and measure to assess improvements over keyword retrieval.

Memrank's BM25 and TFIDF share a tokenizer and document store, isolating their scoring rules
when other settings match. Both run in-process; their latency should not be ranked directly
against HTTP clients. See [methodology](../methodology.md).

## What it needs

No service, API key, network access or download.
